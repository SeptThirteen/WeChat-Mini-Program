# 技术选型对比表

## 一、前端框架选型

| 对比项 | uni-app（Vue 3）✅ 采用 | 原生微信小程序 | Taro（React） |
|--------|------------------------|----------------|---------------|
| 跨端能力 | 一套代码编译到微信/H5/App 等多端 | 仅微信小程序 | 微信/H5/RN 多端 |
| 开发语言 | Vue 3 + Composition API | WXML + WXSS + JS | React JSX + CSS |
| 状态管理 | Pinia（官方推荐） | 需自行封装或用 MobX | Redux / Zustand |
| UI 组件库 | uni-ui + 自定义主题 SCSS | 微信原生组件 | Taro UI |
| 学习成本 | 低（Vue 生态） | 低（官方文档完善） | 中（React 生态） |
| 社区活跃度 | 高 | 高 | 中 |
| **选型理由** | **一次编写多端部署，Vue 学习曲线平缓，适合快速开发毕业设计；Pinia 简洁直观** | | |

## 二、后端框架选型

| 对比项 | Spring Boot 3.2 ✅ 采用 | Express.js (Node) | Flask (Python) |
|--------|-------------------------|-------------------|-----------------| 
| 语言 | Java 17 | JavaScript/TypeScript | Python 3 |
| 成熟度 | 企业级成熟框架 | 轻量级，生态丰富 | 轻量级微框架 |
| ORM | MyBatis-Plus（自动 CRUD） | Sequelize / Prisma | SQLAlchemy |
| 安全框架 | JWT + 自定义拦截器 | Passport.js / jsonwebtoken | Flask-JWT |
| API 文档 | SpringDoc OpenAPI 3.0 自动生成 | Swagger-jsdoc | Flask-RESTx |
| 类型安全 | 强类型编译检查 | TS 可选 | 需 type hints |
| 构建工具 | Maven | npm | pip |
| **选型理由** | **Java 强类型编译期安全，MyBatis-Plus 减少 SQL 编写，SpringDoc 自动生成文档，适合结构化毕业设计** | | |

## 三、数据库选型

| 对比项 | MySQL 8.0 ✅ 采用 | PostgreSQL | SQLite |
|--------|-------------------|------------|--------|
| 类型 | 关系型数据库 | 关系型数据库 | 嵌入式数据库 |
| 性能 | 高并发读写优秀 | 复杂查询更优 | 轻量单文件 |
| 运维成本 | 中等 | 较高 | 几乎为零 |
| 生态兼容性 | MyBatis-Plus 完美支持 | 支持 | 支持但功能有限 |
| 事务支持 | InnoDB 引擎完整 ACID | 完整 ACID | WAL 模式 |
| **选型理由** | **使用最广泛的关系型数据库，MyBatis-Plus 原生支持，文档资源丰富，适合教学和部署** | | |

## 四、AI 引擎选型

| 对比项 | 腾讯混元 ✅ 主引擎 | 百度文心一言 ✅ 副引擎 | OpenAI GPT |
|--------|-------------------|----------------------|------------|
| 接入方式 | TC3-HMAC-SHA256 签名 + HTTPS | access_token + HTTPS | API Key + HTTPS |
| 中文能力 | 优秀（腾讯中文训练） | 优秀（百度中文训练） | 良好 |
| 国内网络 | 直连，延迟低 | 直连，延迟低 | 需代理，延迟高 |
| 免费额度 | 有 | 有 | 无免费额度 |
| 合规性 | 国内合规 | 国内合规 | 需备案 |
| **选型理由** | **国内直连低延迟，中文问答质量高，免费额度充足；双引擎策略模式实现灵活切换** | | |

## 五、鉴权方案选型

| 对比项 | JWT Token ✅ 采用 | Session + Cookie | OAuth 2.0 |
|--------|------------------|------------------|-----------|
| 无状态 | 是（服务端不存储会话） | 否（服务端存储 session） | 是 |
| 跨端支持 | 小程序/H5/Web 均可 | 小程序不支持 Cookie | 流程复杂 |
| 实现复杂度 | 低（JwtUtil 工具类） | 低 | 高 |
| 扩展性 | 好（Claims 可扩展） | 需 Redis 集中存储 | 好 |
| **选型理由** | **无状态适合小程序环境，实现简单，前端 request.js 统一注入 Authorization Header** | | |
